garamond Manual

for Tuatara 0.90.25 and later, every chapter on one page

This manual is written with modal editing on, first and foremost. Where a command also has a key that works with modal editing off, it is given as well, as the non-modal key.

What garamond is

A package that keeps one space or two after a full stop, as the document itself says.

How far apart sentences are is a property of a document, not of the person who edits it. So garamond reads it from the document, from its own Local Variables: block:

# Local Variables:
# sentence-end-double-space: t
# End:

t means two spaces after a sentence's end, nil means one. A file that says nothing is left alone. Where it does say, typing, filling and the sentence commands follow the spacing the file asks for.

It is a package, not part of the editor. It is made from the Emacs package of the same name, by the same author.

1.1 Seeing that it works

Open a file with a Local Variables: block that says sentence-end-double-space: t. The mode line shows 2S. 1S means the file asks for one space between sentences.

1.2 What this manual covers

  • Chapter 2 says how to tell a buffer its spacing, and how to change a whole text to match.
  • Chapter 3 says what typing does and where a second space goes.
  • Chapter 4 lists the settings and describes the command that says why nothing happens.
  • Chapter 5 lists every command and setting.

Setting and changing the spacing

Say how far apart a buffer's sentences are, and make the text match.

2.1 Saying it

M-x garamond-set-spacing says how many spaces, 1 or 2, are between the buffer's sentences. It changes none of the text. Filling, the sentence commands and typing follow the number from then on. A count gives it, as in C-u 2 M-x garamond-set-spacing. Without a count, the command asks, and offers the buffer's own spacing.

When the buffer's file does not say its spacing yet, the command asks whether to write it in the file's Local Variables: block. The file keeps it from then on. A file that says already is kept up to date without asking. The buffer is left modified and not saved.

The command also turns garamond-mode on, unless the buffer is one the mode never runs in (chapter 4).

ModalNon-modalCommandWhat it does
noneM-x garamond-set-spacinggaramond-set-spacingSay how many spaces, 1 or 2, are between the current buffer's sentences, changing none of its text: filling, the sentence commands and typing (M-x garamond-mode, switched on) follow it.

2.2 Making the text match

M-x garamond-adjust-spacing does the same and then changes the text. Every gap after a sentence's end in the selection, or in the whole buffer when there is no selection, becomes 1 or 2 spaces, as one change. A sentence's end is ., ?, !, … or ‽ after a letter, with any closing quotes or brackets, and more text on the same line.

The gap after an abbreviation (for example Dr.) is made one space, as filling leaves it. A list item's number, line breaks, indentation and anything that is not prose are left as they are (chapter 3). A count gives the spacing and otherwise it is asked. Whether to write the spacing in the file is asked only when the whole buffer is changed.

When it has finished, the command says how many sentence breaks it made, and how many gaps after abbreviations it made one space.

ModalNon-modalCommandWhat it does
noneM-x garamond-adjust-spacinggaramond-adjust-spacingMake every run of spaces after a sentence's end in the selection, or the whole buffer without one, 1 or 2 spaces, as one change, then say the buffer uses that spacing as M-x garamond-set-spacing does.

2.3 In the file

A file can also turn the mode on by name, in its own settings:

-*- mode: org; mode: garamond -*-

The mode is not turned on if the buffer is one it never runs in. A file whose own settings are off (the editor's *file-local-variables* setting) is never written to by these commands. They say so instead.

Typing and where a second space goes

What garamond-mode does as you type, and where it leaves the text alone.

3.1 The mode

M-x garamond-mode makes one space typed after a sentence's end two, or stops doing so. It acts only while the buffer's sentences are two spaces apart. The mode line says 2S then. While they are one apart it says 1S, and the mode waits. It also acts only in prose, and never after an abbreviation or a list item's number. A run of more spaces typed is made two.

A count turns it on when it is positive and off when it is zero or less. It is turned on by itself in a file that says its spacing, and by garamond-set-spacing and garamond-adjust-spacing.

M-x garamond-follow-declarations-mode turns that starting by itself on or off, for files opened after it. Its setting, *garamond-follow-declarations*, is on when the package is loaded.

ModalNon-modalCommandWhat it does
noneM-x garamond-modegaramond-modeMake one space typed after a sentence's end two in the current buffer, or stop.
noneM-x garamond-follow-declarations-modegaramond-follow-declarations-modeHave a file that says how far apart its sentences are switch M-x garamond-mode on as it is opened, or stop (GARAMOND-FOLLOW-DECLARATIONS, on as the package is loaded).

3.2 Where a second space goes

Only where prose is written:

  • in a text mode (Org, Markdown, plain text and the rest), never in code, tables, links, maths or a block's contents. Org's parse, or the language's syntax tree, tells which is which;
  • in any other language, only in its comments.

Where a language has a syntax tree that is not ready yet, nothing is doubled.

3.3 Abbreviations

A word whose full stop shortens it (for example Dr. or Sept.) ends no sentence. The abbreviations are Tuatara's own, the ones its sentence commands and filling pass over. Add your own with *extra-sentence-abbreviations* and take any of Tuatara's out with *removed-sentence-abbreviations*, both in the init file. Chapter 2 of Tuatara's manual covers the sentence commands.

3.4 What a sentence's end is

A letter, then ., ?, !, … or ‽, then any closing quotes or brackets. A list item's number (1. or 10.) ends no sentence, because no letter comes before its full stop.

Settings and finding out why nothing happens

The settings, and the command that says what garamond does in a buffer.

4.1 The settings

Set them in the package's :config in your init file:

(load-package "garamond"
              :source "https://github.com/Tuatara-Editor/tuatara-garamond"
              :config
              (setf *garamond-mode-line* nil))
SettingDefaultValuesWhat it changes
*garamond-double-space-on-typing*tt, nilWhether one space typed after a sentence's end becomes two.
*garamond-persist*tt, nilWhether M-x garamond-set-spacing and M-x garamond-adjust-spacing ask to write the spacing in the file.
*garamond-follow-declarations*tt, nilWhether a file that says how far apart its sentences are has M-x garamond-mode on as it is opened.
*garamond-mode-line*tt, nilWhether the mode line says a buffer's spacing while M-x garamond-mode is on in it.
*garamond-unsuitable-modes*(special-mode)a list, each a mode's nameThe major modes M-x garamond-mode never runs in.

special-mode covers the lists, help and terminals Tuatara makes, where nobody writes prose. Garamond will not turn on there and says so.

4.2 Finding out why

M-x garamond-doctor shows in a *Help* buffer what garamond does in the current buffer and why. It lists:

  • the buffer's major mode, and whether its file says its spacing;
  • the spaces between sentences in force, and where they come from when the file does not say;
  • whether garamond-mode is on, and why it will not run when that is so;
  • where a second space goes, and what the mode line says;
  • the settings, and how many abbreviations are in force (Tuatara's, those removed and yours);
  • the likeliest reason for what you see, in a sentence or two.

Press r there to look again after a change.

ModalNon-modalCommandWhat it does
noneM-x garamond-doctorgaramond-doctorShow in Help what Garamond does in the current buffer and why: whether its file says its spacing, the spacing in force, whether M-x garamond-mode is on and where a second space goes, the settings, and the likeliest reason for what is seen.

Every command and setting

Each command and setting of garamond, to look one up by name.

The tables are made from the program each time this manual is made, so they never list a command or setting that garamond does not have. The first table has four columns. The first two are keys: the modal keys, which work only with modal editing on, and the non-modal keys, which work with it off too. A command with no key says M-x and its name in the second column, because you can only run it by its name. The third column is the name of the command and the fourth says what it does.

To run a command by its name, press M-x, type a few letters of the name and press RET. To find a command from within the editor, press C-h f. To find the command that a key runs, press C-h k and then the key. The editor's own settings and commands are in chapters 21 and 22 of its manual.
